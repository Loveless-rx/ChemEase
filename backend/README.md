# ChemEase Docking backend

This local FastAPI service executes Vina and native AutoDock 4 workflows. It is not
part of the GitHub Pages/static JavaScript runtime. Keep the Python service
running while using Docking. Existing molecule editing/analysis and saved
docking PDF/CSV reports remain usable without it.

## Installation

Python 3.12 is the tested runtime. Create an isolated environment from the project
root (use your Python 3.12 executable if `python` points to another version):

```powershell
python -m venv backend/.venv
backend/.venv/Scripts/python.exe -m pip install -r backend/requirements-lock.txt
backend/.venv/Scripts/python.exe tools/install-vina.py
backend/.venv/Scripts/python.exe -m uvicorn docking.api:app --app-dir backend --host 127.0.0.1 --port 8000
```

On Linux/macOS the environment executable is `backend/.venv/bin/python`.
The installer downloads the official Vina 1.2.7 binary and license and checks a
pinned SHA-256 before installing it. Windows x64 execution was tested here;
Linux/macOS downloads are pinned but their execution was not tested on this host.
All generated data, installed dependencies and binaries are ignored by Git and
excluded by the source packager.

### Optional AutoDock 4 / AutoGrid 4

On Windows x64, with official 7-Zip installed:

```powershell
backend/.venv/Scripts/python.exe tools/install-autodock4.py
```

The installer downloads the official Scripps 4.2.6 Windows package, verifies the
package and both executable hashes, extracts only the two binaries without
executing the installer, and installs the GPL license/notice. Both AutoDock and
AutoGrid must pass version checks before the UI enables AutoDock 4.
On other platforms install native 4.2.x binaries from the official project and
set `CHEMEASE_AUTODOCK4` / `CHEMEASE_AUTOGRID4` to their absolute paths. Those
platforms have not been executed on this Windows host. These settings can also
select an existing Windows installation. Unsupported atom types, macrocycle
glue atoms and more than 32 ligand torsions fail explicitly.

After setup, `npm run docking:backend` starts the local service using the project
environment. Start the React app separately with `npm run dev`. The Docking page defaults to
`http://127.0.0.1:8000` and offers a backend-origin setting. Development origins on
localhost/127.0.0.1 are allowed. Example explicit deployment configuration:

```powershell
$env:CHEMEASE_DOCKING_ORIGINS="https://your-frontend.example"
$env:CHEMEASE_DOCKING_DATA="C:/absolute/path/to/private-docking-data"
$env:CHEMEASE_VINA="C:/absolute/path/to/vina.exe"
```

The default data directory is `backend/.data`. Use **one backend process** per
data directory. An OS file lease rejects a second process; SQLite/WAL retains
job/asset records. Unexpected restarts mark interrupted jobs failed, not complete.
Artifact content hashes are checked before reuse/download.

## Local use versus hosted multi-user service

The supplied service binds to loopback. An unguessable browser-local capability
scopes assets, jobs and downloads. It is not student/researcher login, account
authorization or an internet deployment configuration. `scope()` in `api.py` is
the replacement point for authenticated server-side user/organization claims.
For public hosting, add authenticated authorization, HTTPS, explicit CORS,
server quotas, storage lifecycle and a production process/job supervisor before
exposing the service. Remote phones require a reachable, properly hosted backend;
their localhost address refers to the phone itself. A responsive viewport check
does not establish physical-device/backend connectivity.

## Working endpoints

- `GET /api/docking/health`: actual tool/engine readiness and API version.
- `POST /receptors`: multipart `file` or four-character `pdbId`. IDs fetch only
  from the fixed RCSB download host, with time/size limits; arbitrary URLs fail.
- `POST /jobs/receptor`: chain selection, pH, heavy-atom reconstruction choice,
  and explicit confirmation of removal of waters/non-protein residues.
- `POST /jobs/ligand`: one SDF or SMILES molecule, source snapshot and pH.
- `POST /jobs/dock`: prepared asset IDs, grid, exhaustiveness, pose limit and seed.
- `GET /assets`, `GET /jobs`, `GET /jobs/{id}`: scoped immutable preparation
  assets, job history and actual status/result snapshots.
- `POST /jobs/{id}/cancel`: queued/running cancellation. Partial outputs cannot
  be downloaded or treated as completed preparation/docking results.
- `GET /artifacts/{id}/{key}`, `GET /jobs/{id}/archive`: hash-verified files/ZIP.

Except health, requests require `X-ChemEase-Client`, a 32-character lowercase hex
capability generated by the frontend. Do not put capabilities in URLs or reports.
API documentation is available locally at `/docs`.

## Pipeline and scientific scope

See [Docking design and limits](../docs/DOCKING.md). This release runs rigid,
noncovalent **AutoDock Vina** and **AutoDock 4 / AutoGrid 4**. rDock and FlexAID
remain unavailable extension targets. `Engine`/`DockingManager`
separate execution contracts from job orchestration and React. Do not substitute
Vina's AD4 scoring option for the actual AutoDock 4 engine.

One worker runs at a time (Vina uses two CPUs; the tested AD4 build is serial). Up to ten jobs globally/three per
browser workspace may be queued. Jobs have a 30-minute wall limit and a bounded
cancellation grace period before terminating their owned process tree. Stage
messages are real execution states; no simulated search percentage is shown.
Retain at most 200 jobs and 100 raw receptor uploads per backend workspace.
Archive data before administrative cleanup; the app does not silently delete it.

## Checks

```powershell
backend/.venv/Scripts/python.exe -m pytest -c backend/pytest.ini backend/tests -q
npm test
npm run lint
npm run build
```

Unit/API tests use isolated temporary stores. The 1IEP/imatinib end-to-end runs
used real PDBFixer/OpenMM, MolScrub, RDKit, Meeko and Vina, not mocked docking.
Published examples are not universal accuracy validation. Scores are estimates;
each target/protocol needs its own validation and scientific review.
